# План улучшения авторазмещения надписей в AnimaGeo

> Опирается на [аналитический обзор лучших практик](label_placement_research.md)
> и на разбор текущего кода (`animageo/label_placement.py`,
> `animageo/animageo.py`, `animageo/keyframes.py`, `animageo/ui.py`,
> `animageo/labels.py`). Дополняет более ранний
> [`label_autoplacement_plan.md`](label_autoplacement_plan.md) (расширение
> классов препятствий, канонизация имён `F_ab → $F_{ab}$`) — его пункты
> включены сюда как фаза P2-C, чтобы был один сквозной план.

## 1. Контекст и цель

Заказчик хочет, чтобы для **каждого чертежа** надписи: (1) однозначно
привязывались к своему объекту; (2) были видны и читаемы; (3) при невозможности —
минимизировали «штрафы» по (1)–(2); (4) располагались **системно**, без хаоса
(единые отступы, якоря, расстояния).

Текущий механизм AnimaGeo — добротная реализация **жадного PFLP-солвера** (8
направлений, most-constrained-first, аналитические тесты перекрытий, точная
обработка углов, временнáя когерентность для анимации). Он закрывает цели (1) и
(2) на базовом уровне и (4) — для анимации. Главные пробелы — против целей **(4)
системность** (нет канонического порядка позиций и награды за согласованность) и
**(3) деградация** (нет repair-прохода, slider’а, выносок, приоритетов; грубые,
«ступенчатые» штрафы).

Цель плана — закрыть эти пробелы, не ломая обратную совместимость
(byte-for-byte GGB-импорт; авторазмещение остаётся opt-in).

## 2. Как устроено сейчас (карта кода)

**Точка входа.** `overlay.label_placement.enabled=true` → при `applyStyle`
вызывается `autoPlaceLabels()` (+ `_finalize_layout()` для re-fit
`rendered_bounds`). API: `auto_place_labels(scene)` =
`compute_label_layout(scene)` → `apply_label_layout(scene, layout)`.

**Конвейер `compute_label_layout`** (`label_placement.py`):
1. `_collect_labels` — для каждого видимого элемента с `label_visible` строит
   `LabelInfo(anchor, half_w, half_h, margin, preferred_dir, fixed_center,…)`;
   bbox меряется через `_measure_label_bbox` (кэш Tex, thread-safe). **Углы**
   обрабатываются особо: позиция считается аналитически на биссектрисе
   (`compute_angle_label_center`, `fixed_center`, якорь `MC`).
2. `_collect_obstacles` — `segments` (отрезки, клипованные прямые/лучи, рёбра
   многоугольников, векторы), `circles` (круги; **дуги/секторы — как полный
   круг**), `arc_pts` (точки, сэмплы дуг углов).
3. `_compute_preferred_dir(anchor, cloud)` — направление **от** локальной
   плотности геометрии (по умолчанию NE, idx 1).
4. `_solve_greedy` — приоритет «самым зажатым»; углы (`fixed_center`) первыми;
   для остальных — 8 кандидатов `_generate_candidates`, оценка
   `_score_candidate`, при перекрытиях **nudge наружу до +10 px** шагами 1 px.
5. Запись результата: для не-углов якорь из `_DIR_TO_ANCHOR[dir_idx]`, для углов
   — `dynamic_angle` + `AngleParams`; опц. канонизация в `MC`.

**Функция стоимости** `_score_candidate` (минимизируется):
```
cost = w_anchor·dir_penalty            # |idx − preferred_dir| (кольцевая)
     + w_label·Σ площадь_перекрытия(надпись, уже_размещённые)
     + w_geom·Σ (1 + длина_внутри)     # отрезки (Liang–Barsky)
     + w_geom·2.0 · [круг пересекает bbox]
     + w_geom·(число точек внутри bbox)
```
`DEFAULT_CONFIG`: `distance_px=6, padding_px=2, angle_gap_arc_px=3,
angle_gap_sides_px=3, w_anchor=1.0, w_label=10.0, w_geom=8.0`.

**Углы.** `compute_angle_label_center` — биссектриса, `dist = arc_r + max(hw,hh)
+ gap_arc`, narrow-clamp `(half_diag+gap_sides)/sin(half_angle)` с потолком
`×2.5`; `compute_effective_arc_size_px` — авторадиус по
`overlay.angle_radius`. Это аккуратно и соответствует конвенции TikZ
(«eccentricity»); менять не требуется.

**Динамика.** `autoPlaceLabels(dynamic=True)` ставит `_label_tracker`;
`_apply_dynamic_labels` (из `updateVar`) каждые `solver_every_n_frames`
пересчитывает layout, сглаживает `apply_ema_step` + `anchor_hysteresis_step`;
углы — пересчёт центра каждый кадр. `play_keyframes` при
`keyframe_snapshots=true`: `_compute_keyframe_label_layouts` (снимок раскладки в
каждом keyframe) → `KeyframeSequence.attach_label_layouts` →
`LabelOffsetInterpolator` интерполирует статические отступы, углы пересчитываются
покадрово. Это уже соответствует Been/Vaaraniemi/Ekman — трогаем минимально.

**Рендер надписи.** `_build_render_ctx` собирает `label_text/label_spec/
label_offset_px/label_anchor/auto_placed`; `_make_label` → `ui.create_label` →
`_place_label` (`move_to(pos, aligned_edge)` + сдвиг `label_offset_px/ptUnit_ggb`).
9-точечные якоря — `ui.LABEL_ANCHORS`. Это нужные «рычаги»; новый солвер пишет в
те же `elem.style['label_offset_px'/'label_anchor']`.

## 3. Gap-анализ по четырём целям

| Цель | Разрыв | Где в коде | Серьёзность |
|------|--------|------------|-------------|
| **4 Система** | Нет **фиксированного порядка предпочтения позиций**; «предпочтение» = направление от плотности → у похожих точек якоря разные | `_compute_preferred_dir`, `_score_candidate` (`dir_penalty`) | **высокая** |
| **4 Система** | Нет **награды за согласованность** соседей (единый якорь/отступ) | весь солвер | **высокая** |
| **3 Деградация** | Грубые, «ступенчатые» геом-штрафы → плато, нет градиента | `_score_candidate` | средняя |
| **3 Деградация** | Нет **repair-прохода** (greedy застревает) | `_solve_greedy` | средняя |
| **3 Деградация** | Из ступеней деградации есть только `nudge +10px`; нет **slider**, **приоритета**, **скрытия**, **выносок** | `_solve_greedy`, `compute_label_layout` | высокая |
| **1 Ассоциация** | Стоимость не различает **свой/чужой** объект (нет association-терма) | `_score_candidate`, `_collect_obstacles` | средняя |
| **1 Ассоциация** | Отрезки/лучи/прямые/векторы трактуются **как точка** (8 направлений), не параллельно линии | `_collect_labels`, `_DIR_TO_ANCHOR` | средняя |
| **1 Ассоциация** | Дуги/секторы — как **полный круг** (штрафуют пустую часть) | `_collect_obstacles`, `_circle_bbox_intersects` | низкая |
| **1/3** | Конусы/функции/неявные кривые **не учитываются** как препятствия; нет кандидатов для Circle/Conic; бесконечные объекты | `_collect_obstacles` | средняя |
| **2 Читаемость** | Цвет/прозрачность **заливок и линий не учитываются**: тёмная надпись нечитаема на плотной/тёмной заливке; заливки вообще не препятствия, цвет надписи фиксирован | `_collect_obstacles` (нет заливок), `_build_render_ctx`/`ui.create_label` | **высокая** |
| **1 Корректность** | Имена со штрихами/спецсимволами рендерятся как `U_PrimePrime` (мэнглинг python-имени попадает в подпись) | `geo/construction.py` (sanitize `'`→`_Prime`), `labels.py:resolve_label_text` | **высокая** |
| **1/4 Стабильность** | Солвер **игнорирует уже заданное** (ручное/GGB) положение — может перебросить хорошую подпись на другую сторону прямой/объекта | `compute_label_layout`/`_solve_greedy` (всегда считают от якоря) | **высокая** |
| **4 Эстетика** | Для точек-вершин подпись не ставится по **биссектрисе свободного угла** между инцидентными сторонами (как у меток углов) — направление берётся по «центроиду плотности», менее симметрично | `_compute_preferred_dir` | средняя |
| **4 Анимация** | show/hide **«щёлкает»**, не alpha-blend | `keyframes.py`, `_play_keyframe_interval` | низкая |
| (арх.) | Стоимость **зашита в солвер** — нельзя сменить алгоритм | `_score_candidate`/`_solve_greedy` | средняя |

Хорошо/менять не нужно: аналитические тесты перекрытий (Liang–Barsky, circle-bbox)
— соответствуют литературе; обработка углов; временнáя когерентность (EMA +
hysteresis + snapshots); пиксель-инвариантные отступы (`ptUnit_ggb`).

## 4. Предлагаемые улучшения

Каждое: **что** · **зачем** (с источником из обзора) · **где** · **риск/тесты**.
Все поведенческие изменения — **под флагами `overlay.label_placement.*` с
дефолтом, сохраняющим текущий результат** (иначе ломаются snapshot-тесты и
нарушается byte-for-byte импорт). Лучшие дефолты включаем осознанно и обновляем
снапшоты.

### P0 — системность и устойчивость (наибольшая отдача под запрос заказчика)

**P0-C. Отделить функцию качества от солвера (фундамент).**
Вынести стоимость в чистый объект `LabelCostModel` (термы как методы:
`overlap`, `position_pref`, `association`, `consistency`, `soft_proximity`),
а `_solve_greedy`/будущие солверы — принимать его. Зачем: §6.3 обзора (принцип
Edmondson/CMS «scorer ⟂ solver»), позволяет менять greedy→GD→SA без переписывания
качества. Где: `label_placement.py`. Риск: чистый рефактор, поведение неизменно —
закрепить характеризационным тестом «layout до = после рефактора».

**P0-A. Канонический порядок предпочтения позиций + согласованность.**
- Ввести таблицу рангов `POSITION_PRIORITY[dir]` (конфиг
  `position_priority: 'classic'|'perceptual'|'geogebra'`): `classic` =
  Yoeli `TR>TL>BR>BL>R>L>T>B`; `perceptual` = PerceptPPO `T>B>R>TR>BR≥L>TL>BL`
  (§7, §12 обзора).
- В стоимости: `w_pref·rank[i]` (система) + `w_density·angular_dist(i, away_dir)`
  (мягкий тай-брейк в свободную сторону). Сейчас плотность жёстко доминирует и
  порождает «пляшущие» якоря — инвертируем приоритет: канон главный, плотность
  лишь разрешает ничьи.
- **Терм согласованности** (`w_consistency`): пост-проход (или бонус в стоимости)
  — при примерном равенстве стоимости притягивать якорь/отступ к моде соседей
  того же типа, чтобы одинаковые объекты подписывались одинаково (§7 обзора:
  «система = единый порядок × равномерные параметры × награда за согласованность»).
Где: новый `_position_priority`, `LabelCostModel.position_pref/consistency`,
`_compute_preferred_dir` (понизить в ранге до тай-брейка), `DEFAULT_CONFIG`
(`+w_pref, +w_density, +w_consistency, +position_priority`), `compute_label_layout`.
Риск: меняет `test_label_placement` (preferred-direction/scoring/greedy) и
`test_loadggb_snapshot` — вводить за флагом `consistent_placement` (по умолчанию
off → старое поведение), новые дефолты + обновление снапшотов отдельным
осознанным шагом.

**P0-B. Градуированная стоимость + repair-проход.**
- Непрерывное затухание: добавить мягкий штраф близости
  `w_soft·exp(−d/soft_falloff_px)` к геометрии/чужим надписям **даже без
  перекрытия** — у солвера всегда есть градиент, деградация плавная (§6.1 обзора,
  CMS «no plateaus»). Заодно сгладить геом-термы (вместо `1+len`/flat `2.0`).
- `_solve_local_descent`: после greedy — N проходов discrete-gradient-descent
  (для каждой надписи взять кандидата с макс. снижением суммарной стоимости),
  до сходимости; детерминированно. Опц. `anneal: true` — лёгкий SA/random-restart
  для очень плотных сцен с **фиксированным seed** (детерминизм — требование
  системности).
Где: `LabelCostModel.soft_proximity`, новый `_solve_local_descent`,
`compute_label_layout` (вызвать repair после `_solve_greedy`), `DEFAULT_CONFIG`
(`+soft_falloff_px, +repair_iterations, +anneal`). Риск: снапшоты; за флагом.

### P1 — ассоциация и расширение деградации

**P1-A. Ассоциация: own-vs-other + кандидаты для линий + дуги-как-дуга.**
- `LabelCostModel.association`: штраф, если надпись ближе к **чужому** объекту,
  чем к своему (Gestalt-близость; Kakoulis рис.15.2 — §4 обзора); исключать
  собственный объект из препятствий при оценке его надписи.
- Per-type генерация кандидатов: для `Segment/Ray/Line/Vector` — позиции вдоль
  **перпендикуляра** к линии (две стороны), предпочтение «верхней»/внешней;
  side-relative модель Asymptote (§8.2, §10 обзора). (Поворот текста параллельно
  линии — отдельный больший шаг; минимум — корректный перпендикулярный сдвиг и
  выбор стороны.)
- Дуги/секторы трактовать **как дугу**, не полный круг.
Где: `_generate_candidates_for(elem)` (новый, per-type), `LabelCostModel`,
`_collect_obstacles`/`_circle_bbox_intersects` (arc-aware). Риск: средний;
сегментные тесты обновить.

**P1-B. Лестница деградации: slider + приоритет + политика переполнения.**
- **Slider**: непрерывное скольжение по окружности-зазору как ступень перед/вместо
  `nudge` (подписывает на 10–15 % больше в тесноте — §6.3 обзора).
- **Приоритет** `elem.style['label_priority']`: влияет на порядок размещения и на
  то, кто кого вытесняет (важная надпись не штрафуется от менее важной — §9
  обзора, Been/Ekman).
- **Политика** `label_overflow: 'overplot'|'hide'|'leader'`: при безвыходности —
  оверплот (дефолт, как сейчас), либо скрыть низкоприоритетную «осмысленно», либо
  выноска (см. P2-A).
Где: `_solve_greedy`/`_solve_local_descent`, `compute_label_layout`, конфиг.

**P1-E. Подпись точки по биссектрисе свободного угла между сторонами (Цель 4) —
рекомендуется default-on, когда есть место.** По аналогии с метками углов (которые
стоят на внутренней биссектрисе) подпись точки-вершины при наличии свободного
места следует ставить по **биссектрисе наибольшего углового зазора между
инцидентными рёбрами** — т.е. «наружу» от сторон. Это даёт симметричное, опрятное
расположение (см. схему: в `A` и `B` подписи на внешних биссектрисах вершин). Даже
когда внешний угол >180° (стороны не мешают), при прочих равных биссектриса
красивее произвольного из 8 направлений.
- Алгоритм: для точки собрать угловые направления всех инцидентных сегментов
  (стороны/лучи/отрезки, входящие в неё); найти **наибольший свободный зазор**
  между соседними рёбрами; `preferred_dir` = его биссектриса (наружу). Непрерывно
  (хорошо для анимации). Частные случаи: точка на прямой (рёбра 0°/180°) → зазор
  180° → перпендикуляр; одиночное ребро → противоположное направление; нет рёбер →
  текущая density-эвристика.
- Это лишь **preferred-направление** (мягкое предпочтение через `w_anchor`/`w_pref`);
  избегание перекрытий по-прежнему главнее, так что в тесноте подпись сойдёт с
  биссектрисы.
- Где: `_compute_preferred_dir` (для точек с инцидентными рёбрами — заменить
  центроид-эвристику на bisector-of-largest-gap; нужно собрать инцидентность
  точка→сегменты в `compute_label_layout`/`_collect_obstacles`). Можно также
  добавить точную биссектрису как 9-й кандидат (непрерывный угол, не из сетки 8),
  как сделано для углов через `fixed_center`.

**P1-C. Контраст-зависимая читаемость: цвет/прозрачность фона под надписью
(Цель 2).** Сейчас заливки вообще не препятствия (`_collect_obstacles` берёт
только рёбра многоугольников), а цвет надписи фиксирован — тёмная подпись на
плотной/тёмной заливке нечитаема. Две связанные части:
- **Размещение** — учитывать заполненные области (заливки многоугольников/секторов/
  кругов/внутренности коник) как **мягкие препятствия с весом = композитная
  непрозрачность × контраст светлоты заливки относительно цвета надписи**. Тогда
  солвер предпочитает светлые/пустые зоны, а посадку на плотную/тёмную заливку
  штрафует (мягко — это не запрет, см. §6.1 обзора; ср. веса `AreaOver` у CMS).
  Где: `_collect_obstacles` (новый класс «заливки» с цветом/α), новый терм
  `LabelCostModel.fill_contrast`.
- **Отрисовка** — вычислять **эффективный фон** под уже поставленной надписью
  (композит перекрытых заливок/линий с их α поверх фона холста), считать светлоту
  (luminance) и выбирать оформление для контраста: тёмный текст на светлом —
  оставить; на тёмном/плотном — либо переключить на светлый цвет надписи, либо
  добавить **гало/обводку** контрастного цвета (гало — это и пункт P3). Политика
  `rendering.label_contrast: 'off'|'auto'|'halo'`; helper светлоты + композит α.
  Где: `_build_render_ctx`/`ui.create_label` (+ маленький `_effective_bg_luminance`).
- **Связь с Целью 4 (система):** переключение цвета/гало должно быть
  **стабильным** (порог по светлоте + гистерезис в анимации), чтобы подписи не
  «мигали» цветом между кадрами (§9 обзора, D2/D4). Опора: research §5 (Imhof —
  легибельность превыше всего; гало/маски; согласование тон/значение с объектом).

**P1-D. Уважение текущего/ручного положения подписи (Цель 1+4) — рекомендуется
default-on.** Сейчас солвер всегда пересчитывает позицию от якоря, игнорируя уже
заданное (ручное или из GGB) `label_offset_px`; это может перебросить подпись на
другую сторону прямой, хотя текущее положение было хорошим — выглядит странно.
- **Keep-if-good:** если у элемента уже есть `label_offset_px` (не помеченный
  `_auto_placed`) и в текущей позиции нет коллизий — **оставить как есть**.
- **Инерция:** иначе искать, но добавить терм `w_inertia · |кандидат − текущая|`
  (px) и включить текущую позицию в набор кандидатов; выбирается **ближайшая
  приемлемая** позиция (та же сторона, лёгкий сдвиг), а не далёкий «лучший по
  канону». Перескок на другую сторону дорог по инерции → только когда сохранить
  нельзя.
- Согласованность/канон/repair **не перетягивают** уважаемую ручную позицию.
- Это статический аналог принципа временной когерентности (research §9):
  «минимальное изменение хорошей раскладки».
- Конфиг: `respect_current_position` (рекоменд. true), `keep_current_if_free`
  (true), `w_inertia`. Где: `compute_label_layout` (снять текущие центры),
  `LabelCostModel` (терм инерции), `_solve_greedy` (keep-if-good + текущая как
  кандидат), `_repair_pass`/`_consistency_pass` (не двигать уважаемые).

**Отдельная задача — канонизация текста подписей (Цель 1, корректность).**
Не про геометрию размещения, поэтому ведётся параллельно (объединяется с
Phase-1 из `label_autoplacement_plan.md`, где уже есть `F_ab → $F_{ab}$`).
- **Проблема:** `geo/construction.py` приводит GGB-имена к python-валидным
  идентификаторам (`'`→`_Prime`, `&apos;`→`_prime`), и `resolve_label_text`
  рендерит этот **мэнглинг** буквально → видим `U_PrimePrime` вместо `U''`.
- **Источник истины:** оригинальное GGB-имя уже сохранено в
  `constr.name_mapping` (original → normalized); плюс `<caption>` уже
  обрабатывается (`ggb_parser.py:310–320`).
- **Подход:** (a) при парсинге сохранять **оригинальное отображаемое имя** на
  элементе (например, `elem.style['display_name']`), не теряя уникальный
  внутренний идентификатор; (b) добавить в `labels.py` канонизатор
  «имя → TeX»: штрихи (`U'`→`U'` или `U^{\prime}`, `U''`→`U''`, `U'''`→`U'''`),
  подстрочные (`F_ab`→`F_{ab}`, `A_1`→`A_1`), греческие/Unicode (уже есть
  `correctedLabel`); (c) `resolve_label_text`/`resolve_label_spec` берут
  display_name через канонизатор, а явный `label_text`/caption по-прежнему
  выигрывают; (d) экспортеры (TikZ/JSXGraph) используют тот же канонический текст.
- **Грань:** отображаемые имена могут не быть уникальными — это нормально
  (уникальны лишь внутренние идентификаторы).
- **Приоритет:** высокий — это видимая некорректность в любой сцене с
  штрихованными именами (как `fedya26`), а не «улучшение».

### P2 — крупные подсистемы (отдельные фазы)

**P2-A. Внешние выноски / boundary labeling.** При перегрузке (порог плотности
~12.5 % — §5) выносить надписи в поля с leader-линиями; sort-and-stack для
бескроссинговости (порядок надписей = порядок объектов, `O(n log n)`); устранение
пересечений локальной перекоммутацией без роста длины (§8.6 обзора, Bekos и др.).
Нужны: рендер выноски (manim) + поддержка в экспортерах `exporters/tikz`,
`exporters/jsxgraph`, `parsers/svg_parser`.
→ **Готовый мини-план реализации:** [`label_placement_leader_lines_plan.md`](label_placement_leader_lines_plan.md)
(детекция стуковых подписей, free-target/sort-and-stack, модель `LeaderSpec`,
рендер по 4 бэкендам, конфиг `label_overflow`, тесты, порядок работ). Ждёт зелёного
света заказчика; закроет оставшиеся 9 `ok` (совпадающие точки).

**P2-B. Динамика: непрерывная силовая модель + alpha-blend + place-then-select.**
Опциональный force-directed трекер (Vaaraniemi: circle-пружина для точек,
line-пружина для отрезков, биссектриса для углов; трение относительно скорости
объекта) для более плавного движения; alpha-blend появления/исчезновения вместо
«щелчка» в keyframe `show/hide`; «place-then-select» (активные интервалы) для
гарантий D1/D3 (§9 обзора). Где: `_apply_dynamic_labels`, `keyframes.py`,
`_play_keyframe_interval`.

**P2-C. Расширить классы препятствий и канонизацию имён** (из существующего
`label_autoplacement_plan.md`): `Conic/Function/ImplicitCurve` как препятствия
(сэмплинг); кандидаты для `Circle/Conic`; бесконечные объекты (метка прямой `l`
во вьюпорте при скрытых опорных точках); канонизация `F_ab → $F_{ab}$`,
`F1 → $F_1$` в `labels.py`.

### P3 — точечные улучшения
Взвешивание перекрытия линии **по углу** пересечения (вдоль — хуже, поперёк —
терпимо; §5, веса CMS `LineOver`); визуальная иерархия (главные объекты — чуть
крупнее/жирнее, §7); гало/обводка текста при неизбежном наложении.

## 5. Поэтапный план

- **Фаза 1 (P0):** рефактор `LabelCostModel` (P0-C) → канон + согласованность
  (P0-A) → градуированная стоимость + repair (P0-B). Это закрывает «системность»
  и заметно улучшает плотные сцены. Малый-средний объём, всё локально в
  `label_placement.py`.
- **Канонизация подписей** (штрихи/подстрочные) — **параллельная задача,
  желательно как можно раньше** (видимая некорректность `U_PrimePrime`), почти
  независима от размещения; правки в `geo/construction.py`-парсинге +
  `labels.py`.
- **Фаза 2 (P1):** association-терм, per-type кандидаты для линий, arc-aware
  препятствия (P1-A); slider + приоритет + политика переполнения (P1-B);
  **контраст-зависимая читаемость (P1-C)** — заливки как мягкие препятствия +
  выбор цвета/гало по светлоте фона.
- **Фаза 3 (P2):** выноски (P2-A) / динамика (P2-B) / классы препятствий и имена
  (P2-C) — по отдельным мини-планам и приоритету заказчика.
- **Фаза 4 (P3):** косметические улучшения.

## 7. Метрики и верификация

- **Метрика качества раскладки** (новый скрипт-бенчмарк): по батарее `.ggb`/DSL
  примеров считать `Score = overlap_area + Σ pref_rank + association_violations`
  (§6.1 обзора) **до и после**; цель — снижение Score и числа перекрытий.
- **Юнит-тесты новых термов:** монотонность soft-falloff; association-штраф
  растёт при сближении с чужим объектом; `position_priority` даёт ожидаемый
  порядок; consistency-reward выравнивает якоря одинаковых точек; repair не
  увеличивает суммарную стоимость; slider находит щель там, где 8 направлений
  заняты.
- **Детерминизм:** один и тот же вход → идентичный layout (тест), в т. ч. при
  включённом SA (с seed).
- **Визуальная регрессия:** рендер плотных примеров (треугольник с медианами/
  высотами/серединными перпендикулярами; конфигурации с близкими точками) в SVG;
  глазами + автозамер перекрытий.
- **Анимация:** keyframe-рендер, проверка отсутствия мигания/прыжков покадровым
  diff’ом; проверка D1/D3 (метка не появляется/исчезает немонотонно).

DSL-имена и сцены без mapping не затронуты. Тесты:
`tests/test_label_name_canonicalization.py` (10). Прогон — **1420 passed**.

(DSL-сабскрипт `F_ab → F_{ab}` без брейсов — отдельный гейтед пункт на будущее.)

**Раунд 4 — по фидбеку визуальных проверок (round3 + Hermes/Codex).**
Доминирующий сигнал всех раундов: *«не меняй сектор/сторону подписи без нужды»*
(ex16 `M`, ex17 `A`/`B`, ex1 кластер), *«внешняя подпись угла должна оставаться
снаружи»* (ex8/ex21 `45°`), *«подпись не должна уезжать за край»* (ex4 `E12`).
Реализовано (всё за флагом `respect_current_position`, дефолт off → byte-for-byte):

- **FP-5 / FP-7 (сохранение сектора).** В `compute_label_layout` блок respect
  теперь для **любого** ненулевого `label_offset_px` (даже маленького дефолтного
  GGB-отступа) задаёт `preferred_dir`/`bisector_dir` = направление исходного
  отступа. Солвер по умолчанию держит исходную сторону, уходя с неё только при
  реальной коллизии. Это перекрывает density- и `point_bisector`-эвристики для
  объектов с отступом (а `point_bisector` остаётся для объектов **без** отступа).
  Порог `respect_min_offset_px` теперь разделяет *подсказку направления* (любой
  отступ) и *пин позиции* (только существенный отступ ≥ порога).
- **FP-8 (внешние подписи углов).** `AngleParams.exterior` + флипы в
  `compute_angle_label_center` / `compute_angle_label_base_center`. Хелпер
  `_angle_manual_exterior` определяет по существенному ручному отступу, что
  подпись стояла снаружi клина (скалярное произведение `(center−vertex)·bisector
  < 0`), и тогда держит её на внешней биссектрисе вместо снэпа внутрь на стороны.
- **FP-9 (анти-обрезка).** Конфиг `viewport_clamp`: финальный центр статической
  подписи зажимается в границы камеры (`scene._get_scene_bounds`) с учётом
  полуразмеров bbox, поэтому подпись не выходит за холст.
- **Критический фикс резолвера.** Импортированные из GGB `label_offset_px`
  лежат в слое style-config (per_name/defaults), а НЕ в `elem.style`. Код
  размещения читал `elem.style.get(...)` и молча игнорировал все импортированные
  ручные позиции — из-за этого `respect_current_position` фактически не работал
  на реальных `.ggb` (FP-5/FP-7/FP-8 «не срабатывали»). Чтение переведено на
  `_resolve_style(scene, elem, 'label_offset_px')` (как у рендерера). `_auto_placed`
  остаётся на `elem.style` (прямая запись).

**FP-6 — расклейка близких подписей** (раунд 4, по фидбеку про вертикальные
стопки/слипание у почти совпадающих точек): `_declutter_pass` после солвера
раздвигает пары подписей, оставшихся впритык/с наложением, вдоль оси наименьшего
перекрытия — но коммитит сдвиг ТОЛЬКО если он не выводит подпись на геометрию,
которой она раньше не касалась. Поэтому: (а) никогда не меняет «слипание
