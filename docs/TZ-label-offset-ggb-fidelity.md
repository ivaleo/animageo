# ТЗ: соответствие ручных офсетов подписей поведению GeoGebra (WYSIWYG)

**Кому:** команде разработки библиотеки `animageo`
**Модули:** `animageo/ui.py` (`_place_label`, `create_label`), `animageo/animageo.py` (`_render_point`, `_build_render_ctx`), `animageo/parsers/ggb_parser.py`, `animageo/style/scaling.py`, `animageo/label_placement.py` (часть 2)
**Версия, на которой проводился анализ:** `animageo == 1.6.4` (локальная установка)
**Приоритет:** высокий (прямое несоответствие ожиданиям пользователей: «как выровнял в аплете — так и в экспорте»)
**Автор разбора:** диагностика по обращению владельца сервиса animageo-web
**Статус:** части 1 и 2 реализованы в ветке `fix/label-offset-ggb-fidelity` — тесты `tests/test_label_offset_ggb_fidelity.py` (13), ошибки таблицы §2 сведены к нулю, разброс зазоров §6.4 6px → 2px, флип стороны (§5.3) устранён (истинные причины: дуга-как-полная-окружность в препятствиях, потеря интента на повторном прогоне, поворот конусом в `_recompact_pass`). Открыто: перенос семантики в TikZ/JSXGraph-экспортёры; §5.1-нюанс — хвост глифа (Д/Щ) всё ещё входит в bbox при размещении подписи строго над точкой.

**Дополнение (реализовано): размер-инвариантный якорь.** При кегле ≠ родному подпись якорится за проекцию точки привязки на её «родной» (аплетный) bbox — ближняя грань/угол фиксируются, зазор сохраняется точно для любого направления, глифы растут «от точки». Проекция на выпуклый бокс 1-липшицева ⇒ якорь непрерывен по офсету, анимация офсета (включая проход сквозь точку) без скачков, без квантования секторов. На родном кегле — тождественно аплетному размещению. Тесты: `TestSizeInvariantAnchoring` (8 направлений + двухразрешающий критерий непрерывности).

## 1. Краткая суть

Пользователь выравнивает подписи точек в GeoGebra-аплете (перетаскивая их — GGB пишет `<labelOffset x= y=>` в XML). При выключенном автовыравнивании он ожидает, что превью/экспорт покажет подписи **там же относительно точек привязки**. Сейчас каждая подпись систематически смещена **влево и вниз** относительно позиции в аплете.

Измерено на реальной конструкции (см. §2): ошибка по X = −8.3…−10.1 px, по Y = ровно −6.5 px (в пикселях аплета) — на **каждой** подписи. Ошибка складывается из трёх независимых слагаемых (§3).

Вторая часть (§5): при **включённом** автовыравнивании зазор «точка → подпись» неравномерен (7.0–13.0 px на одинаковых настройках) из-за того, что дистанция меряется до tight-bbox TeX, а не до чернил/базовой линии глифа: у «Д» хвосты ниже baseline раздувают bbox на ~28%.

## 2. Воспроизведение и ground truth

**Пример:** https://animageo.ru/shared/Vrf49uRZwVs (публичный; `.ggb`: `GET https://animageo.ru/api/shared/Vrf49uRZwVs/ggb`). Копия лежит в QA-аккаунте `qa-export@animageo.ru` (конструкция `28211471-cd18-4063-819d-173f239696d3`, «Новая конструкция»).

Шесть видимых точек с ручными офсетами в XML (`pointSize=5`, шрифт GGB 16 px, вид 1160×558 @ 50 px/MU):

| точка | labelOffset (x, y экран, y вниз) |
|---|---|
| А | (−6, −4) |
| Б | (−11, 34) |
| В | (−11, 34) |
| Г | (−20, −2) |
| Д | (2, 1) |
| Е | (−18, 30) |

**Семантика GeoGebra** (проверена по исходникам GGB и суб-пиксельно по скриншоту аплета):

```java
// DrawPoint.update():
xLabel = (int) Math.round(coords[0] + 4);
yLabel = (int) Math.round(yUL - pointSize);        // = y - 2*pointSize
addLabelOffsetEnsureOnScreen(...);                  // xLabel += labelOffsetX; yLabel += labelOffsetY
// Далее drawString(labelDesc, xLabel, yLabel): xLabel — ЛЕВЫЙ край (origin),
// yLabel — БАЗОВАЯ ЛИНИЯ текста (не низ bbox), y растёт вниз.
```

То есть у точки:
- **база** подписи (без офсета) = `(x + 4, y − 2·pointSize)` от центра точки — «справа-сверху»;
- ручной `labelOffset` **прибавляется к базе** (не заменяет её);
- позиция задаёт **левый край + baseline** текста.

Эмпирическая сверка по скриншоту аплета: по Y формула сходится с точностью 0.25 px по всем 6 точкам (для «Д» — с учётом хвоста глифа ниже baseline ≈ 2.5 px при 16 px шрифте); по X — с точностью до left-side bearing глифа (~1.5 px, ink начинается правее origin).

**Фактическое поведение animageo 1.6.4** (рендер с конфигом веб-превью: 320×320, `content.fit=contain`, `padding=4`, стиль пользователя «ТВ» с `rendering.label_anchor='BC'`):

| точка | ожидание GGB (лев. край/baseline, MU) | факт animageo (лев. край/низ bbox, MU) | ошибка X, px аплета | ошибка Y, px аплета |
|---|---|---|---|---|
| В | −3.900 / −1.580 | −4.076 / −1.710 | −8.8 | −6.5 |
| Г | −2.900 / 3.040 | −3.065 / 2.910 | −8.3 | −6.5 |
| Д | −0.240 / 2.660 | −0.442 / 2.530 | −10.1 | −6.5 |
| Е | −1.260 / −0.060 | −1.436 / −0.190 | −8.8 | −6.5 |
| А | −3.560 / 2.120 | −3.746 / 1.990 | −9.3 | −6.5 |
| Б | −2.440 / −0.580 | −2.616 / −0.710 | −8.8 | −6.5 |

Фактическая позиция **точно** (до float-эпсилон) воспроизводится формулой «BC-якорь на `точка + offset/ptUnit_ggb` + подъём `0.25·fontSize/ptUnit_style`» — модель ниже верифицирована.

## 3. Корневая причина: три слагаемых ошибки

Рендер ручной подписи точки сейчас (`ui.py::_place_label` + `animageo.py::_render_point`):

```python
# _render_point: pos = ЦЕНТР точки (без GGB-базы)
# _place_label:
mobj.move_to(pos, aligned_edge=edge)                 # edge = style rendering.label_anchor ('BC' у веб-стилей)
mobj.shift([off[0]/ptUnit_ggb, off[1]/ptUnit_ggb, 0])  # off = [x, -y] из XML
mobj.shift([0, ggb_font_px * 0.25 / ptUnit, 0])      # «descender correction», вверх
```

Слагаемые расхождения с GGB:

1. **Нет GGB-базы `(+4, −2·pointSize)`.** animageo меряет офсет от **центра точки**, GGB — от точки «справа-сверху» от неё. Даёт постоянные −4 px по X и −10 px по Y (при `pointSize=5`).
2. **Якорь не GGB-шный.** GGB: левый край + baseline. animageo: `aligned_edge` из стиля — у всех стилей, созданных веб-редактором, это `'BC'` (bottom-center, дефолт `styleConfig.ts`). Горизонтально подпись центрируется вместо левого края → ошибка X зависит от ширины подписи (−полширины: «Д» шире «Г» → −10.1 vs −8.3). Вертикально: низ **tight-bbox** TeX вместо baseline → глифы с выносными элементами («Д», «Щ», «Ц», «у») стоят выше соседей на глубину хвоста.
3. **Эмпирический фадж `+0.25·font` вверх** (введён как «GGB descender correction») компенсирует часть недостающей базы: −10 + 3.5 = −6.5 px по Y. При правильной базе он не нужен и должен быть убран с этого пути.

Дополнительно (структурно; **проявилось и исправлено** — превью редактора стилей, reference 480px на вид 1160px, офсеты сжались ×2.4 и подписи сели на точки): офсеты жили в пикселях **исходного GGB-вида** (`/ptUnit_ggb`, т.е. масштабировались вместе с фигурой при contain-fit), а шрифт — в пикселях **reference-канваса** (`/ptUnit_style`, фикс. размер). В GGB и глифы, и офсет — экранные px, их пропорция переживает любой зум ⇒ ручные офсеты (и база) должны делиться на `ptUnit_style` — то же пространство, что у шрифта и всех прочих декорационных px. Так и сделано (тест `TestOffsetDensityInvariance`).

## 4. Требуемое поведение (часть 1 — ручные офсеты)

Для подписей **точек**, импортированных из GGB (есть `ggb_raw`), при выключенном автовыравнивании (или когда автовыравнивание уважает ручную позицию):

1. Позиция origin подписи в MU:
   `pos = точка + [(4 + offX)/ptUnit_ggb, (2·ps_ggb − offY)/ptUnit_ggb]`,
   где `offX/offY` — сырые значения из XML (y вниз), `ps_ggb` — **сырой GGB `pointSize`** (не стилевой размер точки: пользователь выравнивал подпись в аплете относительно GGB-точки).
   Формула обязана применяться и при **отсутствии** `labelOffset` (offX=offY=0): «нетронутая» подпись в GGB стоит справа-сверху, сейчас animageo ставит её по центру над точкой.
2. Якорь: **левый край + baseline**. Baseline, не низ tight-bbox: «А», «Д», «Б» на одной высоте baseline должны стоять одинаково. (Реализация на усмотрение команды: `\vphantom`-strut при компиляции, вычитание глубины descender'а из bbox, либо метрики шрифта.)
3. Убрать `GGB_DESCENDER_RATIO = 0.25`-фадж на этом пути (он станет двойной компенсацией).
4. `rendering.label_anchor` из стиля **не применяется** к импортированным ручным подписям точек — GGB-семантика важнее эстетического дефолта стиля. Для остальных путей (стилевые подписи, не-GGB сцены) поведение не меняется.
5. Авто-размещённые подписи (`_auto_placed`) не трогать — их round-trip (offset·ptUnit_ggb ↔ offset/ptUnit_ggb, якорь из решателя) уже точен.
6. Опция v2 (обсудить): хранить офсет в em (`off/ggb_font_px`) и применять относительно фактического размера шрифта подписи — закрывает структурную проблему из конца §3.
7. Против GGB-механики `addLabelOffset` (сброс офсета, если подпись уходит за экран) — **не** воспроизводить, это поведение вьюпорта аплета, не документа.

Ожидаемый эффект на примере §2: таблица ошибок → нули (X — с точностью до left-side bearing, Y — точно).

## 5. Требуемое поведение (часть 2 — равномерность автовыравнивания)

Репро на той же сцене, `label_placement.enabled=true`, `distance_px=0, padding_px=0, geom_gap_px=0, angle_gap_sides_px=2` (настройки из сессии пользователя). Измеренный зазор «центр точки → ближайший край bbox подписи» (радиус точки 4 px):

| точка | зазор до bbox, px | высота bbox, px |
|---|---|---|
| В | 10.0 | 12.1 |
| Г | 7.0 | 12.0 |
| Д | 13.0 | **15.5** |
| Е | 7.9 | 12.0 |
| А | 9.0 | 12.6 |
| Б | 9.0 | 12.1 |

Проблемы:
1. **Дистанция меряется до tight-bbox, а не до чернил/нормированного бокса.** Хвосты «Д» (ниже baseline) раздувают bbox → и решатель держит «Д» дальше, и визуальный зазор до тела буквы больше соседних. Предложение: для расчёта дистанции нормировать вертикальный бокс подписи к `[baseline − cap_height, baseline]` (+ небольшой pad), либо считать расстояние до ink-outline. Полный bbox оставить для коллизий подпись-подпись.
2. **Разброс по направлениям.** Диагональные кандидаты (угловой якорь) против кардинальных (рёберный) дают разный видимый зазор при одинаковом номинале — стоит выравнивать по фактическому расстоянию «точка → ink», а не «точка → bbox-грань/угол».
3. **`respect_current_position=true` не удержал ни одну ручную позицию точек** в этом репро (все 6 переразмещены, В и Б — на противоположную от ручной сторону). Уточнить/поправить семантику для точек: ручная позиция без коллизий должна сохраняться (как это уже сделано для углов в `_angle_manual_exterior`).

## 6. Приёмочные тесты

1. **Round-trip тест на `.ggb` из §2** (файл публичен): загрузить без автовыравнивания, для каждой точки сравнить позицию origin подписи с формулой §4.1 (допуск ≤ 0.5 px аплета по Y; по X — ≤ 2 px из-за bearing).
2. Тест «нетронутая подпись»: точка без `labelOffset` → подпись справа-сверху `(x+4, y−2·ps)`, а не по центру над точкой.
3. Тест baseline-выравнивания: подписи «А» и «Д» с одинаковым офсетом → одинаковая базовая линия (разница низа bbox = глубина хвоста «Д», разница baseline = 0).
4. Автовыравнивание: на сцене §2 с нулевой дистанцией разброс зазора «точка → нормированный бокс» между шестью точками ≤ 2 px.
5. Регресс: авто-размещённые подписи и не-GGB сцены — рендер байт-в-байт не меняется.
